# Spec + Plan: 룸 보정, 베이스 매니지먼트, 볼륨 (H16-A 대체)

2026-11-17 작성. 승인 전 초안.

## 목표

Vero V의 atmos67이 Nuprime H16-A 시리즈의 처리 기능 중 다음을 대신한다.

- USB 마이크로 측정하는 **자동 룸 보정**(SECS 2R 엔진): 스피커별 EQ(FIR), 레벨, 지연, 크로스오버, 서브우퍼 정렬
- **베이스 매니지먼트**와 **스피커별 레벨·거리**: 자동 보정의 결과이고, Kodi UI에서 손으로 고치거나 측정 없이 직접 정할 수 있다
- **마스터 볼륨**: Kodi 리모컨의 볼륨 키로 조절한다
- 높이 채널과 서브우퍼를 포함한 출력은 지금처럼 **8채널씩 나눈 AES67 스트림**으로 보낸다

범위 밖: 청취 모드(Pure, Direct 등), 업믹스, HDMI 입력, DTS:X 객체.

## 정한 것 (2026-11-17)

| 항목 | 결정 |
|---|---|
| 보정 엔진 | SECS 2R 공개 크레이트(crates.io, AGPL-3.0-only)를 링크한다 |
| 라이선스 | atmos67은 GPL-3.0. 배포하는 바이너리의 SECS 부분에는 AGPL 조건이 적용된다는 사실을 README에 적는다 |
| 보정 적용 | CamillaDSP를 쓰지 않는다. atmos67이 SECS의 CamillaDSP 내보내기(yml + FIR WAV) 중 SECS가 쓰는 부분만 해석해 처리한다 |
| 볼륨 | Kodi 애드온이 볼륨 변경을 받아 atmos67에 전달한다 |
| AES67 | 8채널 단위 스트림을 유지하고, 출력 채널이 서브우퍼만큼 늘어난다 |

## 구조

```
Kodi ─> 루프백 ─> arecord ─> atmos67 (디코딩·렌더) ─> atmos67 --aes67-send ─> 네트워크
                                                     │  DSP: SECS 신호 체인 + 볼륨
                                                     │  제어 소켓 /run/atmos67/control
                                atmos67 calibrate ───┘  (시험 신호 주입, 마이크는 arecord)
```

- **DSP는 송출기 프로세스에 둔다.** 디코더는 포맷이 바뀔 때마다 다시 시작되지만 송출기는 계속 살아 있다. 그래서 볼륨과 필터 상태가 끊기지 않는다.
- 송출기의 입력은 렌더된 스피커 채널이다. 배치의 역할(L, R, C, Ls, …, Tfl, …, LFE)을 SECS 역할에 대응시킨다. 출력은 메인 스피커 다음에 서브우퍼(SW1…SW8)가 오는 순서다.
- **제어 소켓**(유닉스 도메인, 한 줄 명령)은 다음을 받는다.
  - 볼륨과 음소거
  - 체인 다시 읽기: 파일을 세대 폴더로 바꾸고 진입점 하나만 교체한다(SECS ADR 0018과 같은 방식)
  - 측정 모드 진입과 해제: 일반 재생을 멈추고 DSP를 거치지 않으며, 지정한 출력 하나로 시험 신호를 보낸다
- **보정 형식.** SECS 공개 API는 `SignalChain`을 내주지 않는다. 대신 공개 API로 받는 CamillaDSP 내보내기가 DSP 전체를 기술하므로 이것을 atmos67의 보정 형식으로 쓴다(2026-11-17, SECS 0.25.2의 `secs-camilla`에서 확인).
  - `Biquad`: Peaking, Allpass
  - `BiquadCombo`: LinkwitzRiley와 Butterworth 하이패스·로우패스(차수 지정)
  - `Conv`: Wav
  - `Delay`(샘플 단위), `Gain`, `Mixer`, 파이프라인

  이 밖의 요소가 나오면 거부하고 알린다.
- 보정 모드는 세 가지다.
  - 끔: DSP를 통과시킨다
  - 수동: Kodi 설정으로 만든, FIR 없는 체인을 쓴다
  - 자동: SECS가 계산한 체인을 쓴다

  수동과 자동 모두 레벨, 지연, 크로스오버를 UI에서 고칠 수 있다.

## 측정

- `atmos67 calibrate`는 SECS 공개 API의 `Engine`에 직접 만든 `AudioBackend`를 주입해 쓴다.
  - 출력: 제어 소켓을 통해 송출기로 스윕을 보낸다
  - 입력: USB 마이크를 `arecord`로 녹음한다. 새 ALSA 의존성은 들이지 않는다
- 마이크 보정 파일(UMIK-1 등)과 측정 위치 수(1곳 이상)는 SECS가 지원하는 그대로 받는다.
- 계산은 Vero V에서 한 번 돌린다. 느려도 되지만 진행률을 Kodi에 보여 준다.

## 성공 기준

1. **체인 일치.** 같은 설계에 대해, atmos67이 CamillaDSP 내보내기를 처리해 얻은 경로별 임펄스 응답이 SECS의 `Convolution` 내보내기(입력→출력 경로마다 완성된 임펄스 응답)와 −60 dB 이내로 같다. 설계는 SECS의 시뮬레이션 방(`SimRoom`)으로 시험 중에 만든다.
2. **베이스 매니지먼트.** 수동 체인에서 7.1.4와 서브우퍼 2개 구성일 때 크로스오버 아래 대역이 서브로, 위 대역이 메인으로 가고, 합이 평탄하다(±0.5 dB).
3. **측정 경로.** 알려진 임펄스 응답으로 만든 가짜 마이크로 `calibrate`를 돌리면 SECS가 그 방을 그대로 측정한다. 지연은 1샘플 이내, 레벨은 0.2 dB 이내여야 한다.
4. **볼륨.** 볼륨 변경이 다음 패킷부터 적용되고 끊김이 없다(램프 처리).
5. **성능.** 7.1.4 + 서브 2개, SECS 기본 FIR 길이에서 디코딩, 렌더, DSP, 송출을 합쳐 Vero V에서 실시간으로 처리하고 여유가 있어야 한다. 실기에서 측정한다.
6. 기존 시험이 모두 통과하고, DSP가 꺼져 있을 때의 출력은 지금과 비트 단위로 같다.

## 멈추고 묻는 경우

- D1에서 SECS 크레이트가 armhf로 빌드되지 않을 때. 64비트 userland나 측정만 다른 기기에서 하는 방법 등 대안을 들고 묻는다
- 성공 기준 1을 맞출 수 없을 때(SECS 체인의 의미가 CamillaDSP 출력과 다를 때)
- SECS 크레이트와 `realfft`, yml 파서(`serde_yaml` 계열) 외에 새 의존성이 필요할 때

## 확인하지 못한 것 (실기 필요)

1. 패스스루 중에도 Kodi가 볼륨 키에 `OnVolumeChanged`를 내는지. 내지 않으면 키맵으로 볼륨 키를 애드온 스크립트에 연결한다.
2. Vero V가 성능을 감당하는지(성공 기준 5). 이번 계획에서 가장 큰 위험이다.
3. USB 마이크가 Vero V의 커널에서 잡히는지(`snd-usb-audio`).
4. 보정이 더한 지연(SECS `latency_ms`)이 크면 Kodi 오디오 오프셋을 어떻게 맞출지.
