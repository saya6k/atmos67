### 렌더링과 디코더

- `render.rs` `BedMix::mix`가 입력을 채널 이름 수로 나눴다. 이름이 없으면 패닉, 수가 다르면 채널이 엉뚱한 스피커로 갔다. 이제 디코더가 알려 준 채널 수로 나누고, 이름보다 많은 채널은 버린다.
- `render.rs` LFE가 모든 서브우퍼에 1.0으로 갔다. 서브 2대면 6 dB 커진다. 이제 N대가 1/N씩 받는다(수동 설계와 같은 방식).
- `render.rs` 객체 갱신이 도착 순서대로 큐에 쌓여, 더 이른 시각의 새 갱신이 뒤늦게 적용됐다. 이제 새 메타데이터가 오면 같은 시각 이후로 잡혀 있던 옛 갱신을 지운다.
- `decode/ffmpeg.rs` `reset()` 뒤에도 DTS:X 판정이 참이 돼, DTS를 재생한 뒤 다른 포맷에서 DTS:X 알림이 잘못 나왔다. 이제 다시 연 뒤 실제로 디코딩한 프레임이 있을 때만 판정한다.
- `decode/ffmpeg.rs` 샘플마다 동적 호출과 형식 검사를 했다. 이제 채널(평면)마다 한 번 읽는다.
- `decode/eac3.rs` OpenJOC가 거부한 버스트에서, OpenJOC가 잡고 있던 앞 유닛의 출력(약 32 ms)을 버렸다. 이제 내보낸다.
- `decode/truehd.rs` 유닛 하나가 손상돼도 객체 상태 전체를 지워, 다음 메타데이터까지 객체가 고정 위치로 나왔다. 이제 디코더만 다시 시작하고 객체와 배치는 둔다. 재생이 멈췄을 때의 전체 초기화는 그대로다.
- `dsp/camilla.rs` `bypassed`인 Mixer 단계도 실행했다. 이제 건너뛴다. 믹서의 `channels.in`이 실제 채널 수와 달라도 받았다. 이제 CamillaDSP처럼 거부한다.
- `dsp/conv.rs` 같은 FIR을 쓰는 채널마다 탭 스펙트럼을 새로 계산했다. 이제 필터 하나에 한 번 계산하고 공유한다.

## 시험 환경에서 알게 된 것

- `linux-test`(Apple `container` machine)에서 멀티캐스트를 컨테이너 네트워크로 내보내면 `send_to`와 1 ms 대기가 수십~수백 ms씩 멈춘다. 측정 중에도 VM CPU는 80~100 % 놀고 있었고 메모리 회수도 없었으므로 VM과 호스트 쪽 문제다. 송출기가 타임라인을 다시 맞추게 되고, 그러면 측정이 거부된다.
- 그래서 캘리브레이션 E2E는 바이너리를 네트워크가 있는 컨테이너에서 빌드하고, `--network none --cap-add NET_ADMIN` 컨테이너에서 `ip link set lo multicast on; ip route add 224.0.0.0/4 dev lo`를 한 뒤 실행한다. 네트워크가 없으면 rustup이 툴체인을 받지 못하므로 빌드는 따로 한다.
- VM을 오래 켜 두면 아무것도 안 돌 때도 1 ms 대기가 최대 380 ms 늦었다. 다시 시작하니 42 ms로 줄었다. `container machine stop`은 dockerd가 돌고 있으면 실패하므로 안에서 `pkill dockerd`를 먼저 한다.
- 컨테이너에는 `CAP_SYS_NICE`가 없어 우선순위를 올리는 시험은 효과가 없다(조용히 실패한다).
- 시험 출력은 `| tail`이 아니라 파일로 받고 `timeout -s KILL`을 건다. 멈춘 시험 바이너리가 파이프를 붙잡아 끝나지 않는다.

## 서비스 종료 (`atmos67-run`)

- 송출기는 FIFO(`/run/atmos67/speakers`)에서 입력을 읽는다. 캡처 루프가 그 FIFO에 쓰고, 송출기는 그 입력이 끝나면 큐를 비우고 SAP 삭제 알림을 보낸 뒤 끝난다.
- SIGTERM(systemd의 정지, 또는 그랜드마스터 감시가 보내는 `kill $$`)을 받으면 캡처 루프와 `arecord`를 멈춘다. 디코더가 입력을 잃고 끝나면 FIFO가 닫힌다. 5초 안에 송출기가 끝나지 않으면(루프를 멈추는 순간 캡처가 막 시작된 경우) 송출기를 그냥 끝낸다. 이때는 삭제 알림이 나가지 않는다.
- 송출기가 스스로 끝나면(실패) 나머지를 정리하고 그 종료 코드로 끝나 systemd가 다시 시작한다.
- 컨테이너에서 네이티브 바이너리와 가짜 `pmc`로 확인했다: SIGTERM 뒤 약 1초 안에 두 스트림의 삭제 알림이 나가고 스크립트가 끝났다. 그랜드마스터를 바꾸면 감시 주기(10초) 안에 같은 일이 일어났다. 남는 것은 `sleep` 하나씩이고 systemd가 정리한다.
- 캡처가 돌고 있을 때의 정지도 확인했다. VM 커널에 모듈이 없어 `snd-aloop`을 올릴 수 없으므로, 스크립트 사본에서 루프백의 `hw_params` 경로만 파일로 바꾸고, `arecord` 대신 pid 파일을 쓰고 E-AC-3 IEC 61937 픽스처를 실제 속도로 되풀이해 내는 스크립트를 썼다. 5번 모두(재생 중 2번, Kodi가 루프백을 다시 연 지 0.25초 뒤 3번) 정지 전에 소리가 나가고 있었고(초당 1000패킷 중 약 830개), SIGTERM 뒤 1초 안에 스크립트가 끝났으며, 두 스트림의 삭제 알림이 나갔고, 캡처와 디코더가 남지 않았다. 5초 안전장치가 쓰인 적은 없다. 실제 `arecord`와 `snd-aloop`으로는 실기에서 확인한다.
- `SPEC.md`와 다른 점은 없다(`unsafe` 없음, 새 의존성 없음).

## 실기에서 볼 것

- 송출기 로그의 `the timeline was N ms off the clock`(루프가 밀림)과 `input ran N ms ahead`(입력이 앞섬)가 얼마나 자주 나오는지. 측정 중에 앞의 것이 나면 측정이 거부된다.
- Vero V에서 측정 중 송출 루프가 100 ms 넘게 밀리는지. 실제 네트워크 카드로 보내므로 VM과 다를 것으로 보지만 확인하지 않았다.
- `atmos67 dante aes67`이 `"confirmed": false`를 내는 장비가 있는지.
